# 세피리아 분석

게임 파일을 REA와 IL(관리 코드) 분석으로 뜯어 보고, 공식 모드 API와 그림을 그리는 방식을 정리한 문서입니다. 게임은 실행하지 않고 파일과 이전 실행 로그만 읽었습니다. 예전 LXIUM_sephiria 문서·커밋은 참고하지 않고 새로 했습니다.

> 정확한 근거(REA 근거 ID, 호출 위치, 수치)는 AI용 문서 [`../ai/sephiria.md`](../ai/sephiria.md)에 있습니다. 두 문서는 항상 같이 고칩니다.

## 한 줄 결론

**모드 로더는 게임에 들어 있고(AddOns 폴더), 렌더링 훅은 없습니다.** 그림은 Unity URP 2D가 기본 경로로 전부 그리고, 2D 조명을 **화면 해상도 그대로** 그리는 것과 HDR 빛 번짐이 큰 비용 후보입니다.

## 게임은 어떻게 생겼나

- Unity 6 (6000.3.21f1), **Mono** 빌드 (C# 코드가 그대로 남아 있어 읽기 쉬움)
- 렌더 파이프라인은 URP의 **2D 렌더러**. 2D 조명, HDR, 블룸
- 그 밖에 TextMeshPro(글자), Febucci TextAnimator(글자 애니메이션), Mirror(멀티플레이), FMOD(소리)
- 이 PC: Direct3D 11, Intel Iris Xe

## 공식 모드 API (HorayModAPI)

**불러오는 방식**

1. 게임 폴더의 `AddOns/` 아래 폴더마다 `metadata.json`을 읽습니다 (모드 이름, 버전, 만든이, DLL 파일, 시작 클래스)
2. DLL을 불러와 `HorayModBase`를 상속한 클래스를 만들고 `OnModLoaded()`를 부릅니다
3. 시작 클래스 이름이 틀리면 알아서 찾아 줍니다. 실패한 모드는 건너뜁니다
4. 이 모든 일이 게임 데이터(아이템·무기 등)를 읽기 **직전**에 일어납니다
5. 타이틀 화면에서는 아직 모드가 안 불려 오고, **이어하기·새 게임으로 들어갈 때** 불려 옵니다

`AddOnsDisabled/`는 로더가 보지 않는 폴더라, 모드를 끄고 싶을 때 옮겨 두는 곳입니다.

**모드가 받을 수 있는 이벤트**

| 종류 | 이벤트 |
|---|---|
| 데이터 | 기적·무기·상태·아이템·키워드·패시브·코스튬·소품 데이터를 읽은 직후, 전부 준비됐을 때 |
| 번역 | 번역 준비 때 모드 문장 추가 |
| 게임 흐름 | 게임 시작(서버·클라이언트), 세션 시작, 층 생성 |
| 플레이 | 회피, 디버프 생성, 인벤토리 편집 시작·끝 |
| 네트워크 | 모드 프리팹 등록 |

API 안내문에 "아직 개발 중, 대부분 제대로 안 됨"이라고 적혀 있습니다. **그림 그리기에 관한 이벤트는 하나도 없어서**, 렌더 최적화는 Unity 엔진 기능을 직접 쓰거나 게임 코드를 실행 중에 고치는(Harmony) 방법으로 해야 합니다.

**모드 감지**: 모드가 하나라도 있으면 게임은 "모드 사용 중"으로 보고 오류 보고서 자동 업로드만 끕니다. 게임 플레이에는 영향이 없습니다.

**이 PC에 있는 모드**: CustomSkin, Mira's Item Mod(F1~F3), Sephiria QoL(PageUp/PageDown 등). LXIUM은 F9·F10을 써서 겹치지 않습니다. 게임 자체도 F키를 쓰지 않습니다.

## 그림은 어떻게 그려지나

| 대상 | 방식 |
|---|---|
| 카메라 | 직교 카메라 하나가 월드를 그림. 배경용 카메라가 하나 더 있음 |
| 하루·날씨 | 전역 조명 색이 하루 시간에 따라 매 프레임 바뀜. 안개·비·눈·해와 달·불씨가 화면 전체에 얹힘 |
| 배경 | 패럴랙스 배경을 카메라 영역에 맞춰 타일처럼 깔고 지움 (매번 작은 메모리 할당) |
| 캐릭터·이펙트 | 자체 "스프라이트 넘기기" 애니메이터. 오브젝트마다 매 프레임 따로 돔 |
| 조명 | 2D 조명. 일부는 픽셀 아트 그림(쿠키)을 조명으로 씀. 깜빡임·흔들림도 매 프레임 스크립트로 |
| 바닥 | 타일맵 |
| 빛나는 것 | HDR 색 셰이더 + 블룸 (빛 번짐) |
| UI·글자 | uGUI + TextMeshPro. HUD 일부는 매 프레임 글자를 새로 만듦 |
| 아이템(아티팩트) | 인벤토리 격자의 UI 아이콘 |

게임 코드는 렌더 텍스처나 직접 그리기 명령을 전혀 쓰지 않습니다. 그래서 그리는 방식은 거의 전부 URP 2D 설정에 달려 있습니다.

## 왜 무거울 수 있나 (가설)

1. **2D 조명을 화면 해상도 그대로** 그립니다 (URP 기본값은 절반). 조명은 원래 부드러운 그림이라 낮은 해상도로도 거의 같아 보입니다
2. HDR 색 버퍼와 블룸을 화면 전체 해상도로 처리합니다
3. 안개·날씨·배경처럼 **화면 전체를 덮는 반투명 층**이 여러 장 겹칩니다 (내장 그래픽은 이런 겹침에 약함)
4. 매 프레임 도는 스크립트가 아주 많습니다 (`Update`를 가진 종류만 646개)

이 PC에서는 이미 약 180 fps라 어디가 진짜 병목인지는 재 봐야 압니다. 그래서 첫 버전(0.1.0)은 **재는 도구**입니다. 자세한 계획은 [`sephiria-render.md`](sephiria-render.md)에 있습니다.

## 실제로 재 본 것 (0.3.2)

- 카메라는 하나, 스프라이트는 1유닛 = 16픽셀, 화면 세로로 그림 180픽셀
- 전투 방 하나에 2D 조명 19개, 블룸 하나, 그리기 명령 약 190번
- HUD는 모두 화면 위에 따로 그려져서 월드 해상도를 낮춰도 그대로
- 켜진 스크립트 약 2100개, 그중 매 프레임 도는 것 약 700개 (멀티플레이용 위치 동기화 104개 포함)
- 원래 약 116 fps. 한 프레임 8.4 ms 중 그리기 준비 4.1 ms, 스크립트 2.4 ms
