# 마법소녀의 마녀재판 렌더링 최적화 설계

게임이 그리는 방식을 그대로 두지 않고, 내장 그래픽(Intel UHD 620 ~ Iris Xe)에서도 부드럽게 돌도록 LXIUM만의 렌더링 방식을 만드는 계획과 현재 구현입니다.

> 정확한 근거와 기술 목록은 AI용 문서 [`../ai/mahosaba-render.md`](../ai/mahosaba-render.md)에 있습니다. 두 문서는 항상 같이 고칩니다.

## 출발점

화면에 실제로 보이는 건 배경 한 장, 캐릭터 몇 명, 대사창뿐입니다. 무거운 건 **결과가 똑같은 화면 밖 그림을 매 프레임 다시 만드는 일**입니다. 그래서 "더 빨리 그리기"보다 "**안 그려도 되는 걸 안 그리기**"가 먼저입니다.

## 기능

**A. 설정 바로잡기 (화면 변화 없음, 구현함)**

| 기능 | 하는 일 |
|---|---|
| 2D 카메라 MSAA 끄기 | 2D 그림·UI는 가장자리가 투명이라 MSAA가 하는 일이 없습니다. 3D 법정 카메라의 MSAA는 그대로 둡니다. |
| SSAO는 법정에만 | 구석 음영 효과는 3D 법정에서만 의미가 있어서 다른 카메라에서는 끕니다. |
| 중간 텍스처 필요할 때만 | 캐릭터 합성처럼 필요 없는 곳에서 불필요한 복사를 없앱니다. |
| 프레임 제한 해제 | 60/30 대신 원하는 값으로. 기본은 모니터 주사율에 맞춤(VSync), `-1`이면 제한 없음. |

**B. LXIUM이 직접 바꾼 그리기 방식**

| 기능 | 하는 일 | 상태 |
|---|---|---|
| 바뀔 때만 다시 그리기 | 캐릭터 표정·옷·색이 그대로면 지난 사진을 그대로 씁니다. 배경의 매 프레임 복사도 같은 방식으로 건너뜁니다. 게임이 원래 쓰던 사진을 재사용하는 것이라 화면이 깨지는 일이 없습니다. (힌트의 "프레임 재투영"을 노벨 게임에 맞게 바꾼 것) | 구현 |
| 캐릭터를 화면 해상도로 | 캐릭터 사진을 1440p 기준(1500×3000)이 아니라 지금 화면에 맞는 크기로 찍습니다. 1080p면 픽셀이 56%로 줄고 화면에서는 똑같이 보입니다. 대사·UI는 영향 없음. (힌트의 "공간 해상도"를 캐릭터에만 적용) | 구현 |
| 안 보이는 법정 카메라 끄기 | 화면 분할에서 안 보이는 쪽 카메라는 그리지 않습니다. | 구현 |
| 법정 해상도 맞춤 | 법정 카메라는 화면 크기와 상관없이 1920×1080으로 그렸습니다. 화면(창) 크기에 맞춰 그립니다. 1080p 이상이면 원래와 같습니다. | 구현 (0.1.1) |
| 법정 번갈아 그리기 | 두 법정 카메라를 프레임마다 번갈아 그립니다. 불이 조금 덜 부드러워질 수 있습니다. | 후보 |
| 복사 없이 바로 그리기 | 전환 효과 복사 단계 자체를 없애고 화면에 바로 그립니다. | 후보 |
| 카메라 없이 합성 | 캐릭터 전용 카메라 대신 Naninovel의 가벼운 합성 방식을 씁니다. | 후보 |

**C. LXIUM 전용 셰이더 (준비 필요)**

게임과 같은 Unity 6000.0 에디터로 셰이더를 따로 빌드해야 합니다 (이 PC의 6000.5는 호환이 보장되지 않습니다). 게임의 색조 전환·불빛·블러·페이드를 그대로 받아 같이 움직이도록 만듭니다.

| 셰이더 | 하는 일 |
|---|---|
| ActorDirect | 전환 효과 + 색 + 선명화를 한 번에 화면에 그림 |
| Sharpen | 줄인 그림을 키울 때 선명하게 (FSR의 RCAS 방식) |
| FireLite | 법정 불을 가벼운 방식으로. 불 켜기·불빛 색 전환과 연동 |
| CourtLite | 법정 조명을 고정 조명용 가벼운 계산으로 |

대화 장면은 A와 "바뀔 때만 다시 그리기"만으로 UHD 620급에서도 120fps를 노려볼 만합니다. 재판 장면은 법정 3D가 남아 있어서 법정 쪽 기능과 셰이더가 더 필요합니다. (모두 측정 전 추정)

**하지 않는 것**

- 병렬 처리(Async): 노벨 진행과 Unity 기능은 한 스레드에서만 안전합니다. 그래픽 작업은 이미 엔진이 나눠 돌리고 있습니다.
- 투명 → 불투명(Opaque Ice): 위 기능 뒤에는 투명 그림이 몇 장 안 남아 효과가 작습니다.
- 화면 전체 해상도 낮추기: 대사·UI가 같은 카메라라 글자가 흐려집니다. 대신 캐릭터만 줄입니다.

## 설치해서 써 보기 (런처 전)

1. BepInEx 6 **IL2CPP** 빌드(be.785 이상, Windows x64)를 게임 폴더(`manosaba.exe` 있는 곳)에 풀고 게임을 한 번 실행했다 끕니다 (첫 실행은 오래 걸립니다)
2. `LXIUM_mahosaba.dll`을 `BepInEx/plugins/LXIUM_mahosaba/`에 넣습니다
3. 설정은 `BepInEx/config/LXIUM_mahosaba.cfg` (첫 실행 때 생깁니다)

## 어떻게 확인하나 (렌더 실험실)

1. 설정 파일에서 `RenderLab = true`
2. 캐릭터가 나오는 대화 장면이나 재판 장면에서 **F10**
3. 약 1분 동안 화면을 그대로 둡니다. 원래 상태부터 기능을 하나씩 더하며 8초씩 잽니다 (측정 중에는 프레임 제한을 풉니다)
4. 결과는 `BepInEx/LXIUM_mahosaba/<시각>/` 폴더의 `lab.txt`와 스크린샷. 스크린샷이 서로 똑같아 보이면 "화면 변화 없음"이 맞는 것입니다

## 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| `TargetFps` | 0 | 0 = 모니터 주사율(VSync), -1 = 제한 없음, 숫자 = 그 fps |
| `MsaaOff` | 켬 | 화면 변화 없음 |
| `Ssao` | StageOnly | `Off`면 법정 구석이 아주 조금 밝아짐 |
| `IntermediateAuto` | 켬 | 화면 변화 없음 |
| `ChangeOnly` | 켬 | 화면 변화 없음 |
| `Character Resolution` | 0 (화면 맞춤) | 1이면 원래 크기. 캐릭터를 크게 확대하는 연출이 신경 쓰이면 1 |
| `Stage Resolution` | 0 (화면 맞춤) | 1이면 원래(1920×1080 고정). 0.5처럼 직접 정하면 더 가벼워지고 부드러워짐 |
| `HiddenSkip` | 켬 | 화면 변화 없음 |

게임 옵션의 "포스트 프로세싱"을 끄면 빠지는 건 FXAA뿐입니다 (다른 효과는 원래 0). 글자가 조금 더 선명해지고 가벼워집니다.

## 아직 모르는 것

- 각 기능이 실제로 몇 fps를 올리는지 (Iris Xe 측정 전)
- 캐릭터를 크게 확대하는 장면에서 화면 맞춤 해상도가 티 나는지
- 셰이더용 Unity 6000.0 에디터 준비
