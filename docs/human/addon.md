# LXIUM 애드온 만들기

LXIUM 런처가 설치하고 제거하는 모드 묶음을 **애드온**이라고 부릅니다.
이 문서는 애드온이 왜 이런 구조인지, 어떻게 만드는지 설명합니다.

> 정확한 규칙 목록은 AI용 문서 [`../ai/addon.md`](../ai/addon.md)에 있습니다. 두 문서는 항상 같이 고칩니다.

## 왜 이런 구조인가요?

게임마다 모드를 불러오는 방법(**로더**)이 다릅니다. 어떤 게임은 BepInEx를, 어떤 게임은 MelonLoader를 쓰고,
로더 없이 파일만 넣으면 되는 경우도 있습니다.

더 중요한 건 **사용자가 이미 다른 모드를 쓰고 있을 수 있다**는 점입니다.
번역 모드 때문에 BepInEx를 깔아 둔 사람에게 MelonLoader를 또 설치하면 기존 모드가 깨질 수 있습니다.

그래서 애드온 하나에 로더별 버전(**변형**)을 여러 개 담고,
런처가 게임에 이미 깔린 로더를 보고 맞는 변형을 고릅니다. 아무 로더도 없으면 런처가 맞는 로더를 설치할지 묻습니다.

## 한눈에 보기

애드온은 zip 파일 하나입니다.

```
LXIUM_manosaba-0.8.0.zip
├─ lxium.json                ← 애드온 정보
├─ addon.png                 ← 모드 패널 아이콘 (없어도 됨)
├─ LXIUM_manosaba.lxconfig   ← 설정 설명 (없어도 됨)
└─ bepinex6/                 ← BepInEx 6용 변형
   └─ BepInEx/plugins/LXIUM_manosaba/LXIUM_manosaba.dll
```

변형 폴더 안은 **게임 폴더에 그대로 복사될 모양**입니다.
`bepinex6/BepInEx/plugins/...`는 설치되면 `게임폴더/BepInEx/plugins/...`가 됩니다.

## lxium.json 쓰기

```json
{
  "schema": 1,
  "id": "LXIUM_manosaba",
  "name": "LXIUM manosaba",
  "version": "0.8.0",
  "description": "마법소녀의 마녀재판 렌더링 최적화",
  "game": {
    "id": "manosaba",
    "name": "魔法少女ノ魔女裁判",
    "exe": "manosaba.exe",
    "steamAppId": 3101040
  },
  "variants": {
    "bepinex6": { "minLoaderVersion": "6.0.0-be.785" }
  },
  "tags": ["performance"],
  "replaces": ["LXIUM_mahosaba"]
}
```

| 항목 | 설명 |
|---|---|
| `schema` | 이 규격의 버전입니다. 지금은 `1` |
| `id` | 애드온 고유 이름. 저장소 이름(`LXIUM_게임`)과 같게 씁니다 |
| `name` | 런처에 보이는 이름 |
| `version` | `ver.txt`와 같은 버전 |
| `description` | 한 줄 설명 (없어도 됨) |
| `game.id` | 게임을 구분하는 짧은 영문 이름 (`manosaba`) |
| `game.name` | 게임 이름 |
| `game.exe` | 게임 폴더 안의 실행 파일. 런처는 이 파일이 있는지 보고 올바른 게임 폴더인지 확인합니다 |
| `game.steamAppId` | Steam 앱 번호 (없어도 됨). 있으면 런처가 게임 폴더를 자동으로 찾고, 같은 게임의 모드를 한곳에 모읍니다 |
| `variants` | 지원하는 로더 목록. 이름이 곧 zip 안의 변형 폴더 이름입니다 |
| `minLoaderVersion` | 이 버전보다 낮은 로더가 깔려 있으면 런처가 경고합니다 (없어도 됨) |
| `tags` | 모드 패널에서 거를 때 쓰는 태그 (없어도 됨): `performance` 성능, `utility` 편의, `fun` 재미, `story` 이야기·번역, `msmod` ManosabaLoader 관련 |
| `requires` | 먼저 있어야 하는 다른 애드온 id (없어도 됨). 런처가 먼저 설치할지 묻습니다 |
| `replaces` | 이름을 바꿨을 때 옛 id (없어도 됨). 런처가 옛 것을 지우고 옛 설정을 옮겨 씁니다 |

## 로더 고르기

| 로더 ID | 로더 | 모드 파일 위치 |
|---|---|---|
| `bepinex5` | BepInEx 5 | `BepInEx/plugins/애드온id/` |
| `bepinex6` | BepInEx 6 | `BepInEx/plugins/애드온id/` |
| `melonloader` | MelonLoader 0.6 이상 | `Mods/` |
| `none` | 로더 없음 — 파일만 넣으면 되는 경우 | 자유 |

모두 지원할 필요는 없습니다. **하나 이상**이면 됩니다.
다만 그 게임 모드 커뮤니티가 주로 쓰는 로더는 꼭 지원하는 게 좋습니다.

Unity 게임이라면 먼저 백엔드를 확인하세요. 쓸 수 있는 로더 버전이 달라집니다.

- 게임 폴더에 `GameAssembly.dll`이 있으면 **IL2CPP**
- `게임_Data/Managed/Assembly-CSharp.dll`이 있으면 **Mono**

여러 로더를 지원할 땐 최적화 코드는 한 곳에 두고, 로더마다 다른 "시작 부분"만 따로 만들면 같은 코드를 두 번 고칠 일이 없습니다.

## 런처가 하는 일

**추가** — 애드온 모음에서 찾은 모드는 사용자가 모드 패널에서 **추가**를 눌러야 받습니다. 저절로 설치하지 않습니다.

**설치**

1. 게임 폴더가 맞는지 확인합니다 (`game.exe`).
2. `requires`에 적힌 모드가 없으면 먼저 설치할지 묻습니다.
3. 이미 깔린 로더를 찾습니다. 깔린 로더에 맞는 변형이 있으면 그걸 설치합니다.
   맞는 변형이 없으면 설치하지 않고 이유를 알려 줍니다. 로더를 하나 더 깔면 기존 모드가 깨질 수 있기 때문입니다.
   (`none` 변형은 로더와 상관없으니 이때도 설치할 수 있습니다.)
4. 로더가 없으면 맞는 로더를 설치할지 묻고, 런처가 로더를 설치합니다.
5. `replaces`에 적힌 옛 모드가 있으면 지우고, 옛 설정을 새 이름으로 옮깁니다.
6. 변형 폴더를 게임 폴더에 복사합니다. 원래 있던 파일을 덮어쓰게 되면 백업해 둡니다. 같은 모드를 손으로 넣어 둔 파일은 게임 원본이 아니므로 백업하지 않고 지웁니다.
7. 무엇을 설치했는지 게임 폴더의 `.lxium/` 폴더에 기록합니다. 덮어쓴 원본도 여기에 백업합니다.

**업데이트** — 이전 버전을 지우고 새 버전을 설치합니다. 사용자 설정 파일은 그대로 남습니다.

**제거** — 기록해 둔 파일만 지우고, 백업한 원본을 되돌립니다. 로더는 다른 모드가 쓸 수 있으니 남겨 둡니다. 기록 없이 손으로 넣은 모드도 그 모드 파일만 골라 지웁니다.

## 만들 때 지킬 것

- **로더를 애드온에 넣지 마세요.** BepInEx나 MelonLoader 설치는 런처가 합니다. 애드온마다 로더를 넣으면 버전이 엉킵니다.
- **설정 파일을 넣지 마세요.** 모드가 처음 실행될 때 만들거나, `.lxconfig`가 있으면 런처가 기본값으로 만듭니다. 그래야 업데이트할 때 사용자가 바꾼 설정이 지워지지 않습니다.
- **설정은 로더의 설정 기능으로 만들고, 설명은 `.lxconfig`에 쓰세요.** 그래야 런처의 설정 창에서 여러 언어로 보여 주고, 게임을 실행하기 전에도 바꿀 수 있습니다. ([설정 설명 (.lxconfig)](lxconfig.md))
  - BepInEx: `Config.Bind(섹션, 키, 기본값)`을 쓰고 플러그인 GUID를 애드온 `id`로 → `BepInEx/config/<id>.cfg`
  - MelonLoader: `MelonPreferences` 카테고리의 파일을 `UserData/<id>.cfg`로 지정
  - 설정 파일 자체에는 설명을 달지 않습니다.
- **아이콘을 넣어 주세요.** 저장소 루트에 `addon.png`(정사각형, 256x256)를 두면 모드 패널에 보입니다.
- **모드 파일은 자기 이름 폴더에 두세요.** (`BepInEx/plugins/LXIUM_manosaba/`) 다른 모드와 파일 이름이 겹치지 않고, 손으로 넣은 설치도 런처가 알아봅니다.
- **게임 원본 파일은 되도록 바꾸지 마세요.** Harmony 같은 실행 중 패치를 먼저 쓰세요. 다른 모드와 함께 쓰기 좋고, 게임 업데이트에도 덜 깨집니다.
- **게임마다 저장소를 따로 만드세요.** [LXIUM_sample](https://github.com/LocalXtend/LXIUM_sample)을 복사해 `LXIUM_<게임>` 저장소를 만들고, 게임 분석 문서도 그 저장소에 둡니다.
- **배포는 GitHub 릴리스로 하세요.** `<id>-v<버전>` 릴리스에 zip을 올리면, 그 저장소가 애드온 모음에 등록되어 있는 한 런처가 새 버전을 알아서 찾습니다. ([애드온 모음](catalog.md))

## 자주 묻는 것

**커스텀 API나 자체 로더는요?**
파일만 넣으면 되는 방식이면 `none` 변형을 쓰면 됩니다.
LXIUM 자체 로더처럼 새 로더가 생기면 AI용 문서의 로더 표에 이름을 먼저 추가합니다.

**직접 받은 ManosabaLoader나 .msmod 파일은요?**
모드 패널의 **파일에서 추가**로 고르거나 런처 폴더의 `addons/`에 넣으면 됩니다. 런처가 알아보고 마법소녀의 마녀재판 모드로 보여 줍니다.
- ManosabaLoader 배포 zip: 안에 BepInEx가 통째로 들어 있어도 ManosabaLoader 플러그인 폴더만 설치합니다 (BepInEx는 런처가 따로 관리).
- `.msmod` 파일: 게임 폴더의 `ManosabaMod/`에 넣고, ManosabaLoader가 먼저 필요하다고 알려 줍니다. 버전은 파일 날짜로 보여 줍니다.

**LXIUM 규격을 따르지 않는 남의 모드는요?**
애드온 모음에 "외부 모드"로 등록하면 런처가 그 모드의 릴리스 zip을 받아 필요한 파일만 골라 애드온으로 다시 묶습니다. ([애드온 모음](catalog.md))

**두 변형에 같은 파일이 필요하면요?**
각 변형 폴더에 하나씩 넣습니다. 변형끼리 파일을 공유하지 않습니다.

**규격을 바꾸고 싶어요.**
이 문서와 AI용 문서를 함께 고칩니다. 기존 애드온이 동작하지 않게 되는 변경이면 `schema` 숫자를 올립니다.
